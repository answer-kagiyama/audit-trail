# mvp-issues.md — MVP実装タスク分解

**1 Issue = 1つの明確な成果物。** 依存関係順に並べてある。
各Issueは「実装前に計画を出す → 実装 → lint/typecheck/test/build → レビュー」で進める。

凡例: `⛔` = 先に完了が必要なIssue / `🔀` = 並行着手可

### #36 SQLエディタの複数タブ ✅
- **背景**: 実プレイテストのフィードバック。調査中は
  「さっき書いたクエリを残したまま、別の切り口を試す」場面が多い。
  今は履歴（Alt+↑↓）で戻れるが、2本を**並行して育てる**ことができない
- **完了条件**:
  - タブを追加・切替・閉じることができ、タブごとに独立した編集内容を持つ
  - 実行するのは選択中のタブの内容。Result は実行したタブの結果を出す
  - タブの内容と並びが localStorage に保存され、リロードで戻る
    （保存キーは CASE ごと。`save.ts` の進捗とは別枠にする）
  - タブに名前を付けられる。既定は連番でよい
  - モバイル幅でも破綻しない（タブが増えたら横スクロール）
- **設計メモ**:
  - タブの状態は `ui/SqlEditor/` に閉じる。`game/` は「実行されたSQLと結果」しか
    見ていないので、進行ロジックには一切影響しない
  - CodeMirror のインスタンスをタブごとに作ると重い。
    1つの EditorView に対して `EditorState` を差し替える形にする
    （undo履歴もタブごとに分かれる）
  - 履歴（Alt+↑↓）はタブをまたいで共有でよい。「過去に実行したSQL」は
    タブではなく CASE に属する概念
- **成果物**: `ui/SqlEditor/workspace.ts`（純粋なタブ/履歴の状態、単体テスト27件）、
  `useWorkspace.ts`（保存）、`useCodeMirror.ts` の `EditorState` 差し替え
- 完了条件はすべて達成。設計メモどおり `game/` には影響していない
- ⛔ `#10`

### #41 エディタのタブ列のアクセシビリティ修正 ✅
- **背景**: `#36` でタブ列を足したとき `role="tablist"` / `role="tab"` を名乗らせたが、
  各タブに「閉じる」が同居していて **ARIA のタブパターンの前提から外れていた**。
  矢印キーでの移動も焦点管理も実装しておらず、role だけが先走っていた
- **完了条件**:
  - `role="group"` + `aria-current` にする。選択中は読み上げでも分かる
  - 名前だけで用途が分かる（「クエリ 1 に切り替える」「クエリ 1 を閉じる」）
  - **キーボードだけでタブを切り替えられる**
- **ついでに直したもの**: `indentWithTab` が Tab / Shift-Tab を吸っていて、
  キーボードだけの利用者が**エディタから出られなかった**（WCAG 2.1.2 のキーボードトラップ）。
  Escape を挟むと次の Tab が焦点移動になるようにし、ツールバーに案内を出した。
  これが直るまでは、タブ列を直しても実際には到達できなかった
- **あわせて直したもの**: 遊び方の「画面の見取り図」が2カラム時代のままだった。
  3カラムに直し、掴み手と折り畳みの案内を添えた。
  図と実画面の並びが一致することは E2E で固定してある
- ⛔ `#36`
