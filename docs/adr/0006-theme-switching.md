# ADR-0006: ライト / ダークを切り替えられるようにする

- 状態: **Accepted**
- 日付: 2026-08-23
- 関連: [ADR-0005](./0005-ui-styling.md)（一部を改訂）

## コンテキスト

[ADR-0005](./0005-ui-styling.md) では**単一のダークテーマに固定**した。
理由は「監査ログ端末の質感がそのまま世界観になるので、ライトを併走させる
コストに見合わない」というもので、当時の判断としては妥当だった。

その後 Phase 4 で実際に遊べる状態になり、プレイテストで
「ライトも選べるとよい」というフィードバックが出た。

判断材料が変わった。**遊べる前の予測**ではなく、**遊んだ上での要望**である。

## 決定

**ライト / ダーク / OS追従 の3つから選べるようにする。既定はダーク。**

### 色は1回だけ書く

CSS の `light-dark(ライト値, ダーク値)` を使う。この関数は `color-scheme` を
見て値を選ぶので、切り替えはルートの `color-scheme` を変えるだけで済む。

```css
:root {
  color-scheme: light dark;          /* 既定は OS 追従の状態 */
  --surface-base: light-dark(#f4f1ea, #0f1216);
}
:root[data-theme='light'] { color-scheme: light; }
:root[data-theme='dark']  { color-scheme: dark; }
```

パレットを2ブロック書いて片方だけ直し忘れる、という事故が構造的に起きない。
`@media (prefers-color-scheme)` でパレットを丸ごと複製する書き方は採らない。

### 既定はダークにする（OS には追従しない）

ダークはこのゲームの**アートディレクション**であって、好みの設定ではない。
初めて開いた人には、意図した「監査ログ端末」の見え方で始まってほしい。

OS に合わせたい人は明示的に「OSの設定に従う」を選べる。
選択は localStorage に保存し、既定と同じ値でも明示的に書く
（将来この既定を変えたときに、選択済みの人の見え方が勝手に変わらないように）。

初期表示のちらつきを避けるため、`index.html` の小さなインラインスクリプトで
React のマウント前に `data-theme` を当てる。

## 結果・影響

- **`tokens.css` 以外はほぼ無変更で済んだ。** ADR-0005 で
  「色はすべてトークン経由、CSS Modules に直書きしない」と決めていたため。
  この制約が効いた実例として記録しておく
- CodeMirror テーマの `{ dark: true }` を外した。色はすべて `var()` 経由なので、
  エディタ側にテーマの前提を持たせるとライト時に食い違う
- ライトのアクセントはダークの琥珀をそのまま使えない（白地でコントラスト不足）。
  同じ色相のまま暗くした値を持つ
- 影・バックドロップ・構文ハイライトもトークン化した。
  これらはテーマごとに変える必要がある

## ADR-0005 との関係

ADR-0005 の**「CSS Modules + ヘッドレスプリミティブ」という骨子は変わらない**。
変わったのは「単一テーマに固定する」という一点だけで、そこをこの ADR が上書きする。
