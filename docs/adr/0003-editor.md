# ADR-0003: SQLエディタに CodeMirror 6 を採用する

- 状態: **Accepted**
- 日付: 2026-08-22

## コンテキスト

プレイヤーは1セッションで数十回SQLを書き直す。エディタの品質は体験に直結する。
選択肢は `textarea`、CodeMirror 6、Monaco Editor。

## 決定

**CodeMirror 6 + `@codemirror/lang-sql` を採用する。**

## 理由

| | textarea | CodeMirror 6 | Monaco |
|---|---|---|---|
| バンドルサイズ | 0 | 中（必要な拡張のみ） | **大**（数MB） |
| SQLハイライト | なし | あり | あり |
| モバイル | 可 | 可 | **弱い** |
| 導入コスト | 最小 | 小〜中 | 中 |

- Monaco は VS Code 由来で高機能だが、**バンドルが重くモバイルで実用に耐えない**。
  静的ホスティングの初回ロードにsql.jsのwasmも乗ることを考えると採用できない。
- textarea は最小だが、**SQLの構文ハイライトがないと括弧やクォートの閉じ忘れが見つけにくい**。
  試行錯誤が主活動のゲームでこれは体験の毀損が大きい。
- CodeMirror 6 はモジュール式で、必要な拡張だけ入れれば軽い。

## 制約

- **MVPでは補完（autocomplete）を入れない。** テーブル名補完は便利だが、
  「どのテーブルがあるか調べる」こと自体がゲームの一部。Database画面がその役割を担う
- 導入が難航した場合は **textarea にフォールバックしてよい**。
  Phase 2 をこれでブロックさせない（`SqlEditor` コンポーネント内に閉じる変更なので、
  後から差し替えられる）
